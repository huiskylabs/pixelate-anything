# Contribute a library piece

A contribution is a runnable program, not just a prompt or a picture. Read [the piece contract](references/piece.md) and [the remix loop](references/remix.md). Do not submit borrowed characters, UI or third-party art you cannot redistribute under MIT. State the origin and permission for **every** reference photo, sample, font and asset; a `license: "MIT"` declaration is not proof of permission. The maintainers must review those rights before publication. The migrated San Francisco reference was later identified by its supplier as a Pexels photo; its source file is not redistributed here. That provenance statement is not a precedent for accepting an unlicensed contribution.

## Prepare a local candidate

1. Make a new folder with a valid `piece.json`, source files and an anatomy table that says what each file draws and changes. For a remix, edit `REMIX.md` and keep the local baseline as evidence until you have delivered it. Do not treat the original piece's approval or grade as yours.
2. Save source/reference credits and review trail in `history/` ([history contract](references/history.md)). Keep rejected drafts only with rights clearance and labelled **rejected**, not as good training examples. State which output bytes an independent review actually grades. A gate pass or golden match never creates an art grade, user approval or rights clearance.
3. From a trusted checkout, run `pixelate library --library PATH/TO/LIBRARY add DIR --status study --trust-local-code`. With the default catalog, omit `--library`. An MCP client can instead call `add_piece(piece_dir, library_dir, status="study", trust_local_code=true)` when both the inspected source and destination catalog are inside its workspace. **This executes the candidate's shell commands twice with your permissions and no sandbox**. Run it only for a program you wrote or inspected; never on a stranger's PR or in pull-request CI. It refuses a missing trust flag, a duplicate ID, failing image gate (even for a study), missing outputs and differing bytes across two clean renders. Each clean copy drops generated outputs and gate inputs (`pal`, `pre`, `actor`, `intent`) unless a gate input is explicitly named as an anatomy/knob source; the run must regenerate the rest. An image-free piece reports gate `null`, not a pass. Publishing uses an atomic no-replace directory rename on Linux; on systems without that primitive it refuses to stage rather than risking replacement. On success it stages the piece, writes 1× golden images and rebuilds the deterministic index. It neither reviews art nor verifies permissions. `accepted` needs the contract's static approval/knob/media evidence and independent human confirmation; `reviewed` additionally needs a bound A record. Merely asking for either status cannot prove approval.
4. Check the staged folder, its generated goldens, the index diff, run results and every file for secrets, borrowed IP and unintended outputs. Run `pixelate library test ID` **only on your own trusted code**. Commit the piece, index and any licensed small previews together; open one PR with the request, provenance, reference permissions, changes, technical checks, independent grade if one exists, user approval if it exists and things left untested. Label a technically legal but unreviewed result **NOT REVIEWED**.

## CI and review policy

A pull-request job checks only whitespace and JSON syntax/index membership. It does **not** run unit tests, `library add`, `library test`, `render`, `deliver`, MCP execution tools or any PR program: no sandbox exists for outside code. The PR workflow definition itself is supplied by the PR, so maintainers must keep outside-workflow approval enabled, read-only tokens and no secrets; a green static badge is not a render or security verdict. Only after a maintainer has inspected the exact head and chosen to trust it can they run the full tests and clean-copy render in an isolated environment; those commands remain unsandboxed and should never run on an untrusted fork. Do not promote a piece because the gate or CI passed. No publication or merge while redistribution permissions are unresolved.
