# Library gallery publication

`pixelate gallery` rebuilds the README card block, `docs/gallery/library.md`, this folder's static `index.html`, and the managed `media/` copies from the checked-in `library/index.json`. `pixelate gallery --check` compares them without writing or running piece code. Both reject a stale catalog index. The HTML and copied thumbnails can be served from the `docs/` folder by GitHub Pages after maintainers configure Pages; no Pages deployment or rights approval is implied by generating files locally.

The default `permissions.json` has no approved entries. A card is withheld unless its id is listed with a nonempty rights-evidence path **inside that piece** and the catalog declares a capped PNG/GIF/WebP thumbnail. The ledger is a publication allowlist, **not** proof of permission or an independent art grade. A maintainer must inspect the underlying photo, font, sample and derivative-art licenses and confirm that the owner has authorized redistribution under the declared library license before recording an entry. This is especially unresolved for `san-francisco` (user photo) and `retro-screens` (Pixel Harbor derivative). An entry from a PR is never self-approving. Never add cards or enable Pages for unresolved work. The page reports each manifest's declared status but does not promote it.

`media/` is generated and managed by this tool; do not store unrelated files there. Removing a permission entry removes that copied thumbnail and its card on the next rebuild. Gallery generation is static, but tests, renders and `library add` execute trusted code with no sandbox. PR CI must not invoke any execution tool or a gallery generator supplied by an outside contributor.
