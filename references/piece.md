# Piece manifest (schema 1)

Read this when authoring or migrating a `library/<id>/piece.json`. A catalog entry is a *declaration*, not a certificate that its commands were run. `pixelate find REQUEST` and `pixelate library list|show ID|index` (also `python3 tools/library.py`) validate declarations without executing a piece. `pixelate render DIR`, `pixelate library test` and opt-in `pixelate library add DIR --trust-local-code` run a piece's commands without a sandbox. The latter renders a trusted local candidate twice and stages it as a manual PR, not an art or rights certificate ([CONTRIBUTING.md](../CONTRIBUTING.md)). Render, gate, golden comparison and independent review verification are separate steps. In particular, a technical gate pass is not approval.

## Layout and identity

A piece lives at `library/<id>/piece.json`. `id` is a lowercase ASCII slug (`[a-z0-9]+(-[a-z0-9]+)*`) equal to its directory name; IDs are unique. JSON objects have unique keys. The catalog rejects symbolic links anywhere in a piece, including unreferenced files. All manifest file references are POSIX paths relative to the piece root, with no empty, `.` or `..` component, leading slash, backslash or NUL. Checked-in references (sources, `brief`, `golden`, media, review notes and record, knob `edits`) must exist as regular files. Generated outputs a run command writes (an image `frame`, an audio or export `file`, and the gate inputs `pal`, `pre`, `actor`, `intent`) need not exist before a render; whatever part of their path exists must not be a link, a file used as a folder, or a target that is not a regular file. Validation never takes a declared output as evidence that the piece was rendered. The library root holds only piece directories, the generated `index.json`, and an optional `README.md` or `.DS_Store`. The index is generated, sorted by id, and includes each piece's declared media paths relative to `library/`; it is not proof of quality. Keep full videos outside git.

## Required fields

| Field | Contract |
|---|---|
| `schema`, `id`, `title`, `summary`, `request` | Integer `1`, slug, nonempty human-readable strings. `request` is the original request, not a search-optimized paraphrase. |
| `status`, `mode`, `runtime` | Status: `starter`, `study`, `accepted`, `reviewed`. Mode: `scene`, `rebuild`, `era`, `assets`, `music`. Runtime: `script`, `pack`, `engine`. |
| `tags` | `subject`, `setting`: nonempty arrays of distinct lowercase ASCII slug terms (hyphen permitted). `camera`: `side`, `2:1 iso`, `3/4 top-down`, `one-point perspective`, `two-point perspective`, `oblique`, `military`, `none`. `style`: one of the router styles (`lofi`, `pastel-cell`, `native-glow`, `hd-overworld`, `arcade`, `tactics`, `sticker-iso`, `illustrated`, `neon-noir`, `cosy-lightmap`, `contre-jour`) or `none`. `era`: `nes`, `gameboy`, `pico-8`, `genesis`, `gba`, `neogeo`, `snes`, `none`. `motion`: `stills`, `loop`, `sprite-sheet`, `none`. `sound`: `none`, `music`, `sting`, `sfx`. No other tag fields. Use `none` when a field does not apply. |
| `canvas` | `w`, `h`, `scale`: positive integers (not booleans). |
| `outputs` | Nonempty array of distinctly named typed output records below. `run` is a nonempty shell command that `pixelate render` and `pixelate library test` run; index, list, show and find never run it. |
| `anatomy` | Array of `{file, draws, change_for}`: an existing source file, and nonempty plain-language descriptions of what it draws and what to edit for a change. At least one entry for every status. |
| `knobs` | Object keyed by slug. Each value is either `{values: [distinct JSON scalars], default: one of values, edits: source path}` or `{type: "int", default: integer, edits: source path}`. `edits` names an existing source file. Engine and pack knobs have more rules (see Knobs below) so that each reaches its program. `pixelate render --set` consumes this contract for all three runtimes; the catalog does not apply knobs. |
| `provenance` | `{made: "YYYY-MM-DD", by: nonempty string}`. This identifies who made the piece; it does not attest review. |
| `license` | `MIT` for library contributions. |

Optional: `recipes` (distinct `tools/recipes.py` function names such as `rock_face`; `pixelate library recipes [NAME]` lists the pieces declaring each, not proof their code called it), `kit` (`{tested: nonempty version string}`), `media` (`thumb`, `contact`, `video`, `gif`: optional file paths), `lineage` (`{remixed_from: slug or null}`), `review` (see below). The manifest is limited to 128 KiB.

### Typed outputs

Every output has a unique slug `name`, `kind`, and `run`. The command is metadata, not permission to execute contributed code; unlike `render.json`, a library output always has `run`, because every piece must render in CI.

Image (`kind: "image"`) takes the `tools/render.py` `render.json` image fields, so a `render.json` entry plus `kind` is a valid image output:

| Field | Contract |
|---|---|
| `frame` | Required. The full-size frame the run command writes and the gate checks, at `scale` (for example the 4x frame). A generated output: it need not exist before a render and need not be committed. |
| `golden` | The small tracked 1x golden for `library test`: exactly `out/golden/<name>.png`, never the same file as `frame`; checked in, so it must exist when given. `library test` fails an image without it. |
| `size` | `{w, h}`: positive integers, the 1x size of this image. Defaults to the piece `canvas` `w` and `h`. |
| `style`, `era` | At least one is required for the gate. `style`: a router style (not `none`); `era`: an era above (not `none`). |
| `scene` | A scene variant of `style` (`pixelate style S` lists them); needs `style`. |
| `scale` | Positive integer; the gate defaults to 1. The frame must be `size` times `scale`; `canvas.scale` is not used. |
| `brief` | A source file; must exist when given. Required on the image a `reviewed` record binds. |
| `pal`, `pre`, `actor`, `intent` | Gate inputs the run command may write. Safe relative paths inside the piece; they need not exist before a render, but any component that exists must not be a link, and an existing target must be a regular file. |
| `used` | Comma-separated post ops (`light,shaft`, `rain:hair`). |
| `judge_ignore` | Comma-separated judge defect kinds (`masonry,repeat_units`). |

As in `render.py`, an empty string means an optional string field is unset; no other fields are allowed. Audio: `kind: "audio"`, `file` (audio file). Export: `kind: "export"`, `file` (exported artifact). Gate fields do not belong on audio or export entries. Like `frame`, an audio or export `file` is a generated output that need not exist before a render.

Example (the brief, sources, media and review notes must exist inside `library/quarry-wakes/`; the frame `out/06-a.png`, `out/palette.json`, `out/06-a-actor.png` and `sound/sting.mp3` are written by the run commands; approval must be evidenced, not inferred):

```json
{
  "schema": 1, "id": "quarry-wakes", "title": "The Quarry Wakes",
  "summary": "A machine rises from a flooded quarry.", "request": "a machine rises from a flooded quarry",
  "status": "accepted", "mode": "scene", "runtime": "script",
  "tags": {"subject": ["machine", "quarry"], "setting": ["industrial"], "camera": "side",
           "style": "arcade", "era": "neogeo", "motion": "stills", "sound": "sting"},
  "canvas": {"w": 304, "h": 224, "scale": 4},
  "outputs": [
    {"name": "a", "kind": "image", "run": "python3 art/scene.py A", "frame": "out/06-a.png",
     "style": "arcade", "scale": 4, "brief": "brief.md", "pal": "out/palette.json", "actor": "out/06-a-actor.png"},
    {"name": "sting", "kind": "audio", "run": "python3 sound/sting.py", "file": "sound/sting.mp3"}
  ],
  "anatomy": [{"file": "art/scene.py", "draws": "quarry and machine", "change_for": "subject and composition"}],
  "knobs": {"time": {"values": ["day", "dusk"], "default": "day", "edits": "art/scene.py"},
            "seed": {"type": "int", "default": 17, "edits": "art/scene.py"}},
  "provenance": {"made": "2026-10-18", "by": "agent with art director"},
  "media": {"thumb": "media/thumb.png", "contact": "media/contact.png"},
  "review": {"notes": "history/approval.md", "approved_by": "art-director", "record": null},
  "license": "MIT"
}
```

## Render and test

`pixelate render DIR` reads `DIR/piece.json` (validated as above, so the folder name must equal `id`) or a legacy `DIR/render.json`; a folder with both is an error. Image outputs get the `render.json` behavior: run, gate, era check, judge, optional critique, `render-report.json` and a run record. Audio and export outputs are run and hashed, and their records carry `kind` and `file`. They are never gated: an audio file does not pass the image gate. `--image NAME` selects any output by name. Unlike `library test`, render works in the piece folder itself: outputs of the selected set that share a run command form a group, run once in order of first appearance, and before a group runs its declared `frame` and `file` paths are deleted from `DIR` (a link at the path is removed, never its target; a link or non-folder in a parent folder fails the group's outputs with `unsafe output`, unrun). A stale output from an earlier render therefore cannot pass: the command must write it again, or the output fails as not found with no hash, gate or judge. A failed command leaves the deleted outputs deleted; restore a committed one with git. Generated gate inputs are not deleted. `--no-run` deletes nothing and gates what is there. After a piece command runs, a frame, file or existing gate input (`brief`, `pal`, `pre`, `actor`, `intent`) that is reached through a link or is not a regular file fails that output, and nothing is hashed, gated or judged for it. The frame is read once without following links. The gate and era check run on a private copy of those bytes and of the gate inputs, and the judge and `--critique` read the same bytes, so the recorded hash, in the report and the run record, is of the bytes they all checked, even if a process the command left running rewrites the frame.

With logging on, render keeps those frame bytes at `DIR/.pixelate/snapshots/<sha256>/<frame file name>` (git ignores `.pixelate/`). The report and run record name it as `snapshot`, and the judge and critique corpus records name it as `frame`, so each logged hash points at a file that still holds those bytes. A snapshot is write-once: a later render of other bytes gets a new folder, and a kept file whose bytes no longer match its hash fails the image instead of being replaced. For `--critique`, the brief the gate read is kept the same way and is the brief the critic reads, so its grade in the run record is for the hashed frame and that brief. `.pixelate`, `snapshots` and each snapshot folder are reached without following a link. If one is a link, the image fails (`unsafe snapshot: ...`) and nothing is judged or critiqued. If `.pixelate` is a link, the run record is not written either; render says so and exits 1. With `PIXELATE_NO_LOG=1` nothing is kept and `.pixelate` is not created: the judge and critique read the private copy, which is deleted after the image. Either way, the judge overlay (`<frame>.judge.png`), the critique's thumbnails and its saved critique (`critique-<frame>-lead-rN.md`) go beside the frame in the piece, and `render-report.json` goes in `DIR`. Legacy `render.json` images keep their old path handling: they are hashed, gated and judged in place. `era.ok` is the exit status of `pixelate era`, which prints violations and still exits 0. It means the era check ran, not that the frame is legal. Era legality is decided by the gate's own `--era` lines (`FAIL era ...`), which fail `gate.ok`.

Piece commands run in the piece folder through the shell, with the kit's `tools/` first on `PYTHONPATH`, the kit root first on `PATH` and `PIXELATE_KIT` set to the kit root, replacing any value the caller exported (also in `library test`). `PIXELATE_KNOBS` is set only by `--set` (see Knobs). A program imports kit modules and calls `pixelate assets .`, `pixelate shot . 0` or `pixelate audio . music.wav` without a hard-coded kit path. Legacy `render.json` commands run with the caller's environment, as before.

## Knobs

`pixelate render DIR --set KNOB=VALUE` (repeatable) renders a variant of a `script`, `engine` or `pack` piece without editing it. Each `KNOB` must be declared, and set at most once. An enum value is written as it is spelled in `values`: a string as is, any other scalar as JSON (`true`, `3`, `0.5`); a spelling two declared values share is refused. An `int` value is a plain decimal integer (`-4`, not `+4`, `04` or `4.0`) from -(2^53 - 1) to 2^53 - 1, the integers JSON carries exactly to every runtime. An unknown, malformed, duplicate or out-of-range setting exits 2 before anything runs or is deleted. Render writes the chosen values as a JSON object to a new read-only file in a private temporary folder outside DIR, passes its absolute path to the piece's commands in `PIXELATE_KNOBS`, and deletes the folder after the commands. `piece.json` and the sources are never changed.

Each runtime reads the same file. A script program reads its settings with `knobs()`:

```python
from piece import knobs        # tools/ is on PYTHONPATH for piece commands
k = knobs()                    # {'time': 'dusk', 'seed': 17}: every declared knob, set or default
```

`knobs()` reads `piece.json` in the folder the command runs in (the piece root; pass a folder to read another), checks its knobs, and merges their defaults with the values in `PIXELATE_KNOBS`. It checks that file again: an absolute path to a regular file, opened without following a link, owned by the user and writable by no one else, at most 64 KiB of strict JSON (unique keys, finite numbers) holding an object of declared knobs and values of the declared type. Anything else raises `piece.KnobError`, so the command fails rather than draws an undeclared value. Without `--set`, render and `library test` remove `PIXELATE_KNOBS` from the commands' environment, so a value the caller exported never reaches a piece, and the program draws its defaults, the frames its goldens hold.

**Engine pieces.** `scene.json` holds page metadata and the script list, not art settings, so a copy of it would change nothing; the settings live in the scripts. Instead of a temporary copy of any file, the engine build (`tools/build.py`, used by `pixelate shot`, `video`, `gif`, `audio`, `build` and `check SCENE`) projects the knobs in memory: when the scene folder holds a `piece.json` that declares knobs, the first line after `'use strict'` is `const PIXELATE_KNOBS = Object.freeze({...});`, every declared knob at its default or at the value in the `PIXELATE_KNOBS` file, checked as `knobs()` checks it. The scene's scripts read `PIXELATE_KNOBS.name` (or `PIXELATE_KNOBS['name']` for a hyphenated name), as `starter-scene-loop/scene.js` reads `PIXELATE_KNOBS.horizon`. Keys and string values are written with every character other than an ASCII letter, digit, `_` or `-` as a `\u` escape, so a declared value cannot end its string, close the page's `<script>` element or match a text the builder replaces; an integer outside ±(2^53 - 1) or a nonfinite number is refused. The constant is data: no manifest value becomes code. A `PIXELATE_KNOBS` file in a folder with no `piece.json` stops the build rather than being ignored; a folder with no `piece.json` and no file builds as before, with no constant. For an `engine` piece, the catalog requires each knob's `edits` to be a script the build loads (`config.js`, a `scene.json` `files` entry or `music.js`) that names `PIXELATE_KNOBS.name`.

**Pack pieces.** `pixelate assets` (`tools/assets.py`) sets the `pack.json` options that knobs name, for that export only, in memory; `pack.json` is never written. A `pack` piece's knob must be an enum (`values`) named as the option it sets, with `edits: "pack.json"`. The options a knob may set are listed in `PACK_OPTIONS` in `tools/piece.py`: today only `scale`, an integer from 1 to 64, the export scale of the scaled strips (`<name>@Nx.png`), GIFs, contact sheet, silhouettes and map previews (1x strips, their JSON and the atlas are unaffected). No path or list option can be set. Its `default` must equal the `pack.json` value, same JSON type, so an export without `--set` is the export the checked-in `pack.json` makes; the catalog and the export both check it. A set value replaces the option; `--scale` on the command line together with a set `scale` knob is an error, and so is a `PIXELATE_KNOBS` file with no `piece.json`. `starter-assets` declares `scale` (8 or 4, default 8).

These declaration checks keep a knob wired to its program; they do not prove the program draws each value differently. Only a render shows that: `tests/test_runtime_knobs.py` renders both starters' variants in copies, checks each one differs from the defaults and repeats byte for byte, and checks the defaults still equal the goldens and tracked exports.

With `--set`, each record in `render-report.json` and the run record in `.pixelate/runs.jsonl` carry `knobs: {set, merged, sha256}`: the values set, every knob's value as given, and the SHA-256 of the `PIXELATE_KNOBS` file. They record what the commands were given, not that the program read them. A variant renders in DIR like any render, replacing the declared frames there; it is not compared with the goldens, and its gate pass says nothing about the default frames or about quality. `--set` is refused (exit 2) with `--no-run`, which would gate frames the knobs never drew, and with a legacy `render.json`.

## Library test

`pixelate library test [ID...] [--quick] [--timeout S]` tests the named pieces, or every piece:

1. Validate the manifest and copy the piece to a temporary folder. The source piece is never written.
2. Choose what to test. A full run tests every output. `--quick` tests one kind per piece: its images when it has any, else its exports, else its audio outputs from the first audio command. Every other output is skipped. Group the outputs that are not skipped by identical `run` command, in order of first appearance. Outputs meant to come from one command must declare the same command string.
3. For each group, delete the group's declared `frame` and `file` paths from the copy, then run its command once. Neither a stale committed file nor another command's side effect can pass. A command that runs longer than `--timeout` seconds (default 300) is killed with its process group. Generated gate inputs (`pal`, `pre`, `actor`, `intent`) are not deleted, since they may be checked-in files; they are used as the copy holds them after the group runs.
4. Right after a group runs, check each of its outputs. A path reached through a link, or one that is not a regular file (a folder or a pipe), fails, and nothing is read from it. Each output is read once, without following a link. Its hash, golden comparison and gate all use those same bytes, so a process the command left running cannot make them describe different frames.
5. For an image, the frame must exist and be `size` × `scale` pixels. The frame is reduced to 1x with nearest-neighbor sampling, and its RGBA pixels must equal `golden` exactly. A difference reports the pixel count, the bounding box `[x0, y0, x1, y1]` and the largest channel delta. To accept a change, update the golden in the same commit. Separately, the frame runs the same technical gate as `pixelate render` (`pixelate check` with the image's `style`, `era`, `scene`, `scale`, `pal`, `pre`, `actor`, `used`, `intent` and brief section, plus `pixelate era` when it names an era). The gate runs on a private snapshot of those frame bytes and of the gate inputs; the brief is taken from the source piece. The report keeps `golden`, `gate` and `era` apart and sets `gate_ok`. `era: {ran, report}` records only that `pixelate era` ran and its last lines: it prints violations and exits 0. Era legality comes from the gate's `--era` lines, so an era frame of the wrong size, too many colours or too many tiles fails `gate` even when it matches its golden exactly. A gate that exits 1 counts as a verdict only when its summary (`FAIL: N of M checks`) is the last line it prints and no traceback follows. For a `starter`, `accepted` or `reviewed` piece, an image passes only if the golden matches and the gate passes. A `study` only has to render (plan section 2.1). Its gate failure is reported (`gate_ok: false`, the failing lines, and a `diagnostic`) and does not fail the image. A gate that errors instead of finishing, such as a crash on a malformed gate input or a failed era check run, fails the image whatever the status. A link or non-regular gate input also fails it.
6. For audio and export: the file must exist and be nonempty; its SHA-256 is reported. `--quick` skips the kinds it did not choose and reports each such output as `skipped` with a `reason` and `tested: false`. A piece with images therefore has its audio and exports skipped in quick mode; an export-only piece such as `starter-assets` or `meadow-kit` runs its export commands and checks every declared file is newly written; an audio-only piece runs its first audio command and reports its other audio commands as untested.

The command prints JSON: `{ok, gate_ok, quick, pieces: [{id, ok, gate_ok, kinds, outputs: [{name, kind, path, status, tested, ...}]}]}`, where `status` is `passed`, `failed` or `skipped`, `tested` is false exactly for a skipped output, and `kinds` maps each declared kind to `{declared, tested}` counts. A piece is `ok` only when no output failed and at least one passed, so a piece whose outputs were all skipped is never green. A piece's `gate_ok` is true only when every one of its images ran and passed the gate, so `ok: true` with `gate_ok: false` means a study rendered and matched its goldens but is not gate-legal. It is `null` for a piece with no image: nothing was gated, and it says nothing about the legality of a pack's sprites or exports. The top-level `gate_ok` covers only the pieces that have images, and is `null` when none does. It exits 0 when no output failed, 1 when one did, and 2 for a malformed or unknown ID, an invalid manifest, or when no piece is selected (for example, an empty library). A golden match is a regression test, and a gate pass is a technical check. Neither is a quality judgment or approval.

`library test` is for trusted, checked-in pieces; `library add --trust-local-code` is for a trusted local candidate only. The shell is not a sandbox: a run command can read and write anything the user can, before or after the checks. The link checks keep a trusted piece's mistakes from being verified as its own output; they do not contain hostile code. Do not run it on contributed or pull-request code until the project adopts a trust and sandbox policy.

The root `.gitignore` ignores `out/` folders. Under `library/<id>/out/` it ignores everything except `golden/`, so `git add` picks up golden frames. Commit the small 1x golden; `library test` regenerates the full-size frame, so it need not be committed. A scaled frame needs `git add -f` unless git already tracks it.

## Status evidence

| Status | Required static evidence | Still requires outside catalog validation |
|---|---|---|
| `starter` | A tagged, anatomized piece with at least one output and provenance. | Render and gate on the *empty starter* before use. It is a fallback, not a recommended finished base. |
| `study` | Same static declaration. | CI render; no approval implied. |
| `accepted` | At least two knobs; at least one image output; `media.thumb` and `media.contact` files; `review.notes` file and `review.approved_by` (`user` or `art-director`). | Verify approval is genuine, render determinism and gate result. Review notes are not a technical gate result. |
| `reviewed` | All accepted evidence plus `review.record` file (a visual-review sidecar) and matching A-grade artifact-bound review via `review_status.piece_status`, so the exact reviewed frame must exist even though frames are otherwise generated. | Recheck exact-byte binding after any file change; review alone does not grant licensing or user approval. |

`review` is `{notes: path or null, approved_by: "user" | "art-director" | null, record: path or null}`. For `starter`/`study` it may be absent; if supplied, all references are checked, but it cannot elevate status. `record` is a sidecar produced by `pixelate review record`, named `<frame>.visual-review.json` beside an image output's `frame`, with the critique report saved inside the piece (for example `history/lead.md`) before recording. The record keeps the absolute paths it was made at, so a moved piece is checked by `review_status.piece_status`: the recorded frame must end in the output's `frame` path under a directory with the piece's id, the recorded brief must be the output's `brief` under that same directory, and the report must have been inside it. Only those paths are reanchored to the piece's current folder; no link is followed. A report recorded outside the piece, a renamed piece, a different path relation, a link, noncanonical record bytes, changed brief/frame/report bytes, or a B/C grade fails `reviewed` validation. Plain `pixelate review status` keeps binding absolute paths. Accepted review notes must be nonempty. For `accepted`, review notes/approval are declarations to audit, never inferred from a passing gate. Do not promote migrated work to accepted without evidence.

## Search contract

Search requires a mode match and at least one request word that matches a `tags.subject` term other than a deliverable-format word (`asset`, `icon`, `sheet`, `sprite`, `spritesheet`, `tile`, `tileset`); a format word can add score after another subject matches, but cannot make a piece relevant alone. Explicit camera, style, era or motion mismatches are not interchangeable. This holds for starters too: a request that names `Game Boy`, `one-point perspective`, or `still` or `loop` is offered only a starter whose tag equals it. Words are lowercased and singularized, and common function and filler words (`its`, `out`, `up`, `old`, `make`, `pixel`) never count. Setting tags (`day`, `outdoor`) and words of the title, summary and request add score to a piece that already matches a subject, but cannot make a match on their own, so choose subject tags for what the piece can be remixed into. A status bonus only orders relevant results; it cannot turn an unrelated popular or reviewed piece into a match. `find` returns at most three matched pieces plus `starter` fallback(s) for the requested mode that meet every explicit tag of the request (with no explicit tag, every starter of the mode). When nothing is close it abstains from recommending a finished piece and returns the starter plan, or an author-new-piece plan if no compatible starter exists, never a starter of different art. `tools/library_search_cases.py` contains 20 labelled, author-created requests drawn from the actual corpus (17 pieces and three starter fallbacks) plus five negative requests. `tests/test_library_search_regression.py` checks the expected piece in the top three or an honest fallback; these corpus-aware, in-sample cases are not an unseen-request benchmark or evidence of art quality. The synthetic and false-match cases in `tests/test_library.py` exercise the matching rules.
